# OpenCode Companion

Ранее — OpenCode Model Sync. Модели, агенты, MCP, рабочие пространства и настройки OpenCode в одном приложении. Существующий конфиг, язык интерфейса и список исключённых пространств сохраняются. Старая команда `opencode-model-sync` остаётся совместимым псевдонимом.

[English version](README.md)

Настольное приложение для Linux, macOS (Apple Silicon) и Windows. Оно опрашивает ваши серверы моделей и добавляет найденные модели в конфиг [opencode](https://opencode.ai). Работает с обычным opencode, форк не нужен: opencode сам замечает изменение конфига.

## Что умеет

- Показывает провайдеров из `~/.config/opencode/opencode.json`, у которых указан свой адрес API, и проверяет, отвечают ли они.
- Ollama, LM Studio, vLLM, llama.cpp и любые OpenAI-совместимые серверы, локальные или в сети.
- Для Ollama и LM Studio берёт реальный размер контекста и поддержку инструментов. Модели эмбеддингов пропускает.
- «Синхронизировать» добавляет новые модели. «Удалить из конфига» удаляет отмеченные модели, например те, которых больше нет на сервере.
- Две независимые кнопки с постоянными названиями. Подсвеченная кнопка включена, приглушённая — выключена:
  - **Отображение** — показывает или скрывает модель в каталоге OpenCode через конфиг. Настройки модели сохраняются.
  - **Инструменты** — включает или выключает поддержку вызова инструментов у модели.
- Работает только один экземпляр Companion для текущего пользователя. Повторный запуск открывает уже работающее окно, в том числе из трея. После аварийного завершения блокировка снимается при следующем запуске.
- Находит локальные серверы на стандартных портах, которых ещё нет в конфиге, и предлагает их добавить.
- Конфиг меняется только по нажатию кнопки. Перед первой записью рядом сохраняется резервная копия `opencode.json.bak-model-sync-*`.
- Переименовать или удалить провайдера можно через меню **⋯**. Переименование сохраняет ID, удаление также сбрасывает выбор моделей этого провайдера в настройках.
- На вкладке «Рабочие пространства» видно папки, в которых работает opencode, и там можно убрать застрявшие строки.
- Сворачивается в трей. Тема светлая или тёмная, как в системе. Интерфейс на русском и английском.

Новые провайдеры на всех ОС записываются в документированный раздел `provider` с полями `npm` и `options`. Изменение моделей и переключение отображения сохраняют этот формат. Существующие записи `providers` поддерживаются для совместимости и автоматически не переносятся.

Вкладки «Настройки» и «MCP» редактируют `.jsonc`, сохраняя комментарии и неизменённые значения. Старые действия синхронизации провайдеров и редактирования агентов по-прежнему не перезаписывают файлы с комментариями.

## Ввод изображений

В списке провайдеров показываются **Изображения**, **Без изображений** или **Изображения ?**, если поддержка неизвестна. Учитываются `vision` из нативного API Ollama, тип `vlm` у LM Studio и явные сведения о входных модальностях/vision у совместимых серверов. По названию модели поддержка не угадывается. Отсутствие метаданных (например, у `iq3_s` в Strata) не означает отсутствие поддержки изображений.

**Синхронизировать** теперь дополняет сведения об изображениях и у уже добавленных моделей. Явный список входных модальностей, в том числе только `text`, имеет приоритет над сервером. Другие модальности, инструменты, лимиты, имена и пользовательские настройки сохраняются. Переключатель **Изображения** у добавленной модели позволяет включить или отключить ввод картинок вручную.

Если метаданных нет, нажмите **Тест** рядом с нужной моделью. После подтверждения Companion отправит до двух небольших случайных синтетических изображений через OpenAI-совместимый `/chat/completions`, вне потока интерфейса. Это может загрузить модель и стоить денег за генерацию; таймаут каждого запроса — 60 секунд. Личные изображения не используются. Фоновое обнаружение и синхронизация генерацию не запускают. HTTP 200 недостаточно: оба ответа должны правильно определить формы, цвета и расположение фигур. Ошибки сети, неподдерживаемые параметры и неубедительные ответы оставляют результат неопределённым и не меняют конфиг. Успешный тест включает изображения; новая модель при этом добавляется в конфиг. Учитываются переопределения адреса, API ID модели и авторизации; перед записью проверяется, не изменился ли провайдер или модель за время запроса.

Сохраняется существующий формат конфига:

- `provider` / `npm` / `options`: `models.<id>.modalities.input = ["text", "image"]`, `modalities.output = ["text"]`.
- `providers` / `package` / `settings`: `models.<id>.capabilities.input = ["text", "image"]` с сохранением остальных возможностей.

Заданные входные и выходные модальности сохраняются; выключение удаляет только `image` из входных. Используются штатные резервные копии и атомарная запись. Как и другие изменения провайдеров, JSONC с комментариями не перезаписывается; тест не начинается, если результат нельзя безопасно сохранить. Форматы сверены с [модельной схемой OpenCode 1.x](https://github.com/anomalyco/opencode/blob/v1.2.27/packages/opencode/src/provider/models.ts) и [актуальной схемой провайдера](https://github.com/anomalyco/opencode/blob/dev/packages/schema/src/config/provider.ts).

## Настройки и MCP

Пять самостоятельных вкладок: «Провайдеры», «Рабочие пространства», «Агенты и команды», «MCP» и «Настройки».

- В «Настройках» доступна схема `opencode.json` для OpenCode 2.1.4: 29 основных разделов со всеми вложенными полями и 19 старых разделов совместимости V1. Категории и поиск помогают найти нужный параметр, включая `experimental.subagent_depth`.
- Фиксированные варианты выбираются в выпадающих списках. Вложенные объекты и упорядоченные списки редактируются формами; произвольные данные сторонних SDK и плагинов — как JSON. Названия и подсказки переведены на русский и английский.
- «Не задано» не записывает значение в файл: сохраняются наследование и штатные значения OpenCode. Настройки проекта или управляемые политики могут переопределить глобальную конфигурацию.
- На вкладке MCP можно добавлять, редактировать и удалять локальные и удалённые серверы. Флажок включает сервер или выключает через `disabled`; название строки не меняется. Общие тайм-ауты раскрываются отдельно.
- Запись выполняется по кнопке «Сохранить». Черновик сохраняется при переходе между вкладками и переключении языка. Проверяется схема, создаётся резервная копия; независимые внешние изменения объединяются, конфликтующие не перезаписываются.
- При изменении параметров и после сохранения показывается, когда они вступят в силу. Для параметров запуска сервера выводится предупреждение о перезапуске; для интеграций — о возможном переподключении. OpenCode автоматически не закрывается и не перезапускается.

## Агенты и команды

На отдельной вкладке «Агенты и команды» видно, на какой модели работает каждый агент opencode, и это можно поменять. Модели в окне выбора сгруппированы по провайдерам; группы можно сворачивать.

- **Собрать команду**: планировщик на сильной модели плюс несколько исполнителей (программист, тестировщик, ревьюер, исследователь или свой), у каждого своя модель. Планировщик становится основным агентом и может отдавать задачи только своим исполнителям. Если отмечено «только раздаёт задачи», он не правит файлы и не запускает команды. Исполнители становятся сабагентами, и каждый получает только тот доступ, который нужен его роли: тестировщик не правит файлы, ревьюер и исследователь ничего не меняют.
- **Новый агент** и **Изменить**: имя, описание, тип (основной, сабагент или оба), модель, инструкции, температура, доступ к правке файлов, командам и вебу, список сабагентов, которым агент может раздавать задачи. Встроенные агенты `build`, `plan`, `general` и `explore` настраиваются под своими именами.
- Модель выбирается из тех, что подключены в opencode: приложение спрашивает список у самого opencode (`opencode models`). Поэтому в списке есть и локальные модели, и бесплатные облачные из opencode Zen и OpenRouter. Пометки «бесплатная», «локальная», «вызов инструментов» и размер контекста берутся из конфига и каталога [models.dev](https://models.dev), которым пользуется opencode. Каталог кэшируется на сутки. Скрытую через «Отображение» модель среди вариантов агента не предложить, хотя `opencode models` её всё ещё перечисляет. Агент с моделью, которой нет среди подключённых, помечается.

Командную строку opencode приложение ищет в `PATH`, в папках установочного скрипта, npm и bun, а также внутри OpenCode Desktop на Windows, macOS и Linux. Если она лежит в другом месте, укажите путь в переменной окружения `OPENCODE_CLI`. Если её не найти, список моделей берётся из конфига.

Новые агенты записываются в раздел `agent`, формат которого описан в документации opencode. Агента из нового раздела `agents` приложение правит там же, но его правила доступа оставляет как есть. Настройки, которыми приложение не управляет (`color`, `steps` и другие), сохраняются.

## Каталог MCP

Откройте **MCP → Добавить из каталога**. Источники:

- **Для начала** — встроенная подборка Context7, Sentry и Grep из [документации OpenCode](https://opencode.ai/docs/mcp-servers/#examples), а также Playwright и GitHub из инструкций их разработчиков. Работает без сети.
- **Официальный реестр MCP** — поиск актуальных версий через публичный API [MCP Registry](https://registry.modelcontextprotocol.io/), с загрузкой следующих страниц.
- **Glama** — отдельные списки репозиториев и удалённых серверов. [API Glama](https://glama.ai/mcp/reference) требует ключ: введите его в окне каталога или задайте `GLAMA_API_KEY` перед запуском приложения. Введённый ключ используется только в этом окне, не записывается в конфиг OpenCode и не отправляется в другие каталоги. Каждая запись содержит ссылку на Glama; рекламные записи отмечены.

Выберите запись и вариант подключения, нажмите **Настроить и добавить…**. Форма показывает адрес или точную команду, позволяет изменить имя, добавить HTTP-заголовки либо переменные окружения и оставить сервер выключенным. Для значений можно использовать ссылки `{env:ИМЯ}` на окружение OpenCode. Локальным серверам нужны Node.js (`npx`), uv (`uvx`) либо Docker; само приложение их не устанавливает. Просмотр каталога ничего не запускает.

Если источник не публикует готовые параметры запуска, откройте ссылку разработчика и заполните адрес/команду вручную. Пакеты с неподдерживаемыми аргументами тоже требуют ручной настройки. Приложение не угадывает имя пакета по адресу GitHub. Записи с одинаковым именем не перезаписываются.

Добавление заполняет черновик на странице MCP. Нажмите **Сохранить**, чтобы записать сервер в `mcp.servers` (формат OpenCode 2.1.4, используемый редактором настроек). JSONC-комментарии и посторонние параметры сохраняются, перед записью создаётся резервная копия. Сохранение включённого сервера позволяет OpenCode подключиться или запустить локальную команду. При OAuth после сохранения выполните вход в OpenCode или `opencode mcp auth ИМЯ`. Состояние можно проверить командой `opencode mcp list`.

## Рабочие пространства

Чтение базы поддерживает OpenCode 1.x (`session`, `project.sandboxes`) и новые схемы (`session_v2`, `worktree`). Если время активности отсутствует, используется время изменения или создания проекта. Если схема не поддерживает удаление или архивирование, эти кнопки отключены; «Исключить» остаётся доступным и не изменяет OpenCode.

На вкладке «Рабочие пространства» — папки, в которых работает opencode, и созданные из них git worktree. Это тот же список, что opencode показывает в своей боковой панели. Строки от папок, которых на диске уже нет, остаются в этом списке навсегда, а экрана, где их убрать, в opencode нет.

- «Исключить» убирает пространство только из этого приложения. opencode при этом не тронут, папка остаётся на месте. Галочка «Показывать исключённые» возвращает скрытые строки, кнопка «Вернуть» — одну конкретную.
- «Удалить» обращается к самому opencode. worktree удаляется через `DELETE /api/worktree` тем же способом, каким был создан; если в нём есть незакоммиченные изменения, приложение спросит отдельно, удалять ли их вместе с ним. Папку проекта opencode помечает как архивную в своей базе — именно так он и убирает её из своего списка: папка и её сессии остаются, а если открыть эту папку в opencode, она вернётся.
- Архивные opencode пространства с этого списка скрыты, как скрыты они и у самого opencode. Галочка «Показывать архивные» показывает их, «Вернуть из архива» убирает пометку, и пространство возвращается в список opencode.
- «Добавить папку» передаёт папку запущенному opencode — ровно так же, как она появляется там, когда её открывают в opencode.
- В строке видно, осталась ли папка на диске, является ли она git worktree, сколько сессий opencode для неё сохранил и когда в ней работали последний раз. В меню **⋯** — «Открыть папку».

Пока opencode запущен, список берётся из него через `opencode api`; иначе те же строки читаются из `~/.local/share/opencode/opencode.db`. Перед первой записью в базу opencode рядом сохраняется копия `opencode.db.bak-model-sync-*`. Список исключённых пространств — свой файл приложения, `~/.config/opencode/model-sync-workspaces.json`.

## Скачать

Сборки для всех систем приложены к [последнему релизу](../../releases/latest). Сборки не подписаны:

- **macOS:** распакуйте архив, при первом запуске нажмите на приложение правой кнопкой и выберите «Открыть».
- **Windows:** распакуйте архив в новую пустую папку и запустите `OpenCode Companion.exe`. Не распаковывайте поверх старой сборки: оставшиеся DLL могут помешать запуску. SmartScreen может попросить подтверждение.
- **Linux:** распакуйте архив и запустите `opencode-companion/OpenCode Companion`.

## Запуск из исходников

Нужен [uv](https://docs.astral.sh/uv/).

```bash
uv run opencode-companion
```

## Сборка

Каждая система собирает своё приложение:

```bash
uv run python scripts/build.py
```

Результат появится в `dist/`: `.app` на macOS, папка с `.exe` на Windows, папка с исполняемым файлом на Linux, плюс архив. На Linux установка в меню приложений:

```bash
sh scripts/install-linux.sh
```

Сборки для всех трёх систем делает GitHub Actions: при публикации тега `v*` workflow `build` собирает их и прикладывает к релизу.

## Тесты

```bash
uv run pytest
```

## Обновления

Нажмите **номер версии рядом с переключателем языка → Проверить обновления**. Companion проверяет последний стабильный релиз GitHub для текущей ОС и архитектуры. Нажмите **Скачать обновление**, затем **Установить и перезапустить**. Архив проверяется по SHA-256; папка приложения заменяется после его закрытия. Предыдущая версия сохраняется по пути, указанному в диалоге, и восстанавливается при ошибке замены папки. Конфигурация OpenCode находится отдельно и сохраняется.

Автоматическая установка доступна в собранном приложении, расположенном в доступной для записи папке. На macOS сначала переместите приложение в доступную для записи папку Applications. На Windows после выхода заменяется вся папка приложения; на Linux — текущая папка установки. Ошибки сети, отсутствие сборки для архитектуры и ошибки проверки архива показываются без замены приложения. Исходники обновляются через Git. Проверка и установка запускаются пользователем; скрытой фоновой установки нет.
